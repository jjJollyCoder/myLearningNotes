## 2️⃣ 关于模块拆分与代码封装的理解

- 在一个项目中，很多功能是**复用**的，比如读取配置、分类规则、日志打印等。
- 反复复制粘贴会让代码难以维护，于是我开始把功能模块单独拆出来，变成一个个函数或文件。

### ✅ 封装的理解：
- **封装 = 功能的独立 + 对外暴露接口**；
- 一般是写成函数或类的方法，并通过 `return` 返回执行结果：
  ```python
  def load_config(path):
      with open(path) as f:
          return json.load(f)
````

* 这样其他模块只需调用，而不需要了解里面的细节，提高了可维护性与可复用性。

### ✅ 模块化带来的好处：

* 易读、易测、易扩展；
* 在 CI/CD 流程、多人协作、写测试时非常重要；
* 这是我第一次深入体会到“代码结构设计”和“工程化思维”的价值。

## 🧗 过渡建议：从「会用工具」进阶到「理解系统」

下面是你可以一阶阶突破的路径：

### Step 1️⃣：明确你要调用的 API 到底在哪

* 打开浏览器开发者工具 → `Network`；
* 手动点你要模拟的页面（如 radar 页面）；
* 找出对应的请求路径（比如 `/api/radar/details?id=...`）；
* 复制这个请求（可用 Chrome 的 “Copy as cURL”）放到 Postman 里试着复现。

👉 **这一步核心不是成功调用，而是知道真实请求结构长什么样。**

---

### Step 2️⃣：理解认证机制的分类

| 常见认证类型           | 判断方式                                      | 使用方式                |
| ---------------- | ----------------------------------------- | ------------------- |
| Bearer Token     | 请求 header 中有 `Authorization: Bearer xxxx` | 只要 token 有效就能直接复用   |
| Cookie + Session | 请求 header 有 `cookie: sessionid=...`       | 需要先登录一次拿 cookie     |
| OAuth / SSO      | 请求被重定向到某认证平台                              | 需要做完整授权流程（难）        |
| CSRF Token       | 页面里埋 token，需要放到 POST 请求里                  | 要先 GET 一次拿 token，再用 |

👉 你可以用 Postman 或 `curl` 模拟请求一步步试，先从 **只要带上 cookie/token 就能请求成功的 API** 开始。

---

### Step 3️⃣：从复用别人的 API 请求脚本入手

你不一定从一开始就“定义”一个 API 调用，可以先从以下方式：

* 请求你熟悉的开发伙伴，提供 API 示例请求体（postman/curl）；
* 看是否有内部 API 文档系统，比如 Swagger；
* 若都没有，也可以问一句：「你们是怎么调用这个 API 的？有什么请求样例可以参考吗？」

---

### Step 4️⃣：循序渐进写你自己的 Python 调用脚本

比如你可以用 `requests` 模块这样开始：

```python
import requests

url = "https://radar.company.com/api/getRadarList"
headers = {
    "Authorization": "Bearer YOUR_TOKEN",
    "Content-Type": "application/json"
}
payload = {"ids": [1234, 5678]}

resp = requests.post(url, json=payload, headers=headers)
print(resp.status_code)
print(resp.json())
```

如果 `YOUR_TOKEN` 不是你能直接获取的，那就暂时别 focus 在这类 API 上，先找能复用 cookie 的接口。
